- **Depth:** depth 1 loses nothing here. The published 21 September run gave the same totals at depth 1 and at depth 2.

## 9. Caveats

- The checks use English-only vocabularies. French or Czech wording for helpdesk or policy pages is not recognised; Data Terra's "Contact & accès" was judged by reading it.
- PDFs and other binaries are not read. The one PDF that mattered was read manually during this review.
- Screenshots cover the first screen only. Logos further down the page are found in the markup but not seen.
- A logo drawn as an SVG or a CSS background can be missed by the markup check, as happened for CERN and Czechia. Those cells stay MANUAL_REVIEW by design, never FAIL.
- Point 4 does not request the eosc.eu target page; the expected slugs in `nodes.yaml` were read from the eosc.eu index.
- Italy was not assessed: eosc.it has no A or AAAA record, and www.eosc.it is NXDOMAIN.

Items 1–3 were fixed in commit `29dead8`, and their effect is in section 12. Item 4 is still open.

1. *(fixed)* Point 6 should not PASS on link text alone. It should require helpdesk wording on the target, or at least flag funding and press pages.
2. *(fixed)* Point 5b/5c should match the link href (e.g. `acceptable-use-policy`) as well as the link text.
3. *(fixed)* The 5b/5c reviewer action says "Re-run with --depth 1" even in a depth-1 run when the target is a PDF. It should say that the target is a binary file the tool doesn't read.
4. *(open)* Name matching accepts "EOSC Node - X" and "EOSC Node X" for "EOSC Node | X". That is the documented behaviour, but the report should state it next to each match.
